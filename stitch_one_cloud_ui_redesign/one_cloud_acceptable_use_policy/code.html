01

Core Principles

One Cloud provides an indexed, sovereign file directory interface built upon Telegram’s distributed protocol infrastructure. The platform is designed exclusively for legitimate personal file storage, productive retrieval, and lawful archival.

As an authenticated account holder, you hold ultimate ownership and direct responsibility for every binary payload, media artifact, directory namespace, and shared access link generated through your instance. Users are bound to observe both local legal jurisdictions and international software usage norms.

verified Personal Sovereignty

Storage boundaries are linked directly to your authentic Telegram session credentials.

gavel Strict Accountability

Zero tolerance for using cloud nodes to circulate unlawful or abusive file systems.

02

Prohibited Content & Media

You may not upload, index, share, or broker through One Cloud any material that conflicts with standard software security laws or human safety protocols. Prohibited categories include, but are not limited to:

  • bug_report

    Malicious Software & Exploits

    Viruses, keyloggers, ransomware bundles, rootkits, exploit kits, or executable droppers designed to compromise remote infrastructure.

  • security

    Exfiltrated Credentials & PII

    Unlawfully acquired databases, compromised session secrets, credential lists (combo lists), or Personally Identifiable Information traded without express consent.

  • copyright

    Copyright Infringement & Piracy Rings

    Bulk distribution clusters hosting copyrighted cinema, music catalogs, or cracked proprietary software releases.

  • shield_person

    Harmful, Exploitative, or Unlawful Imagery

    Non-consensual sexual material, non-consensual exploitation, violent terroristic propaganda, or any state-sanctioned illegal artifacts.

info

Content Custody Notice

Because binary storage is hosted inside your personal Telegram account via bot gateways, material uploaded through One Cloud must also strictly comply with Telegram’s Terms of Service and Community Standards. Actions taken by Telegram against an underlying account will directly impact your One Cloud index access.

03

System Integrity & Operational Abuse

We engineer One Cloud with low-latency indexing pipelines and resilient cache layers. To guarantee continuous stability for all network tenants, the following operational activities are strictly prohibited:

dns Infrastructure Stress

Launching Distributed Denial of Service (DDoS) simulations, stress testing endpoints, or flooding sync tunnels without authorized consent.

terminal Reverse Engineering

Decompiling obfuscated runtime engines, attempting to bypass token authentication filters, or falsifying user session scopes.

hub Scraping Directories

Crawling, enumerating public file IDs through brute-force queries, or accessing virtual directories not provisioned for public display.

04

Telegram Platform Guidelines

One Cloud communicates through MTProto and standard Telegram Bot APIs. Safe integration requires strict adherence to official Telegram Developer Boundaries:

upload_file
Telegram File Constraints Single binary file sizes cannot surpass Telegram's native file upload boundary (currently 2 GB for regular bot streams or 4 GB for Telegram Premium accounts).
speed
Flood Protection (HTTP 429) Do not run scripted workers designed to intentionally circumvent Telegram rate limits. Violations risk immediate Telegram IP-level quarantines.
smart_toy
Dedicated Bot Security Keep bot tokens securely stored inside the One Cloud vault. Do not share active bot tokens across unverified external services.
05

Resource Fair Use & Rate Ceilings

While Telegram provides generous cloud message storage, One Cloud provisions high-performance edge caching, file hierarchy parsing, and thumbnail indexing services. To protect server health:

Metadata Indexing API 60 req/min

Applies to automated CLI tools and directory syncing queries. Excessive calls are throttled dynamically.

Concurrent File Transfers 8 streams

Per-account transfer thread ceilings to ensure equal socket bandwidth distribution across user bases.

Automated bot-farm swarms, headless media scraping spiders, or distributed file locker mirroring setups without explicit commercial enterprise agreements are deemed fair-use violations.

06

Violations & Enforcement

We utilize a disciplined, graduated response mechanism when handling policy incidents. Responses vary depending on severity, intentionality, and past conduct:

1

Automated Ingestion Warning

For minor protocol overages or accidental malformed payloads, a warning notification and temporary rate dampener is dispatched to your active session.

2

Temporary Index Suspension

Repeated unauthorized traffic leads to temporary API key deactivation and metadata freeze (your underlying Telegram data remains intact inside your telegram client).

3

Immediate Account Termination

Direct involvement in ransomware distribution, unlawful imagery distribution, or hostile security attacks triggers immediate termination and permanent IP blacklist.

07

Reporting Abuse

If you identify an active One Cloud sharing gateway or public download link hosting malicious files, copyright-infringing archives, or illegal material, please submit a rapid-response notice.
